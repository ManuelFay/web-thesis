\chapter{Personal Perspectives on Search}

\label{ch:conclusion}

Vannevar Bush had the vision that searching using \emph{associative} links would be the key insight to unlock new retrieval capabilities \cite{bush1945aswemaythink}. Time proved him right, well aided by the advent of computing. Statistical retrieval engines revolutionized fixed classification systems by linking information queries to documents through their words, not just their general topic. Deep neural networks further strengthened these associative links by moving beyond surface-level syntax and instead exploiting semantic proximity. The contributions of this thesis could be seen as further efforts to improve \emph{search} by exploring the extent to which we can create associative links.

At a high level, with \emph{Visual Document Retrieval} \sidecite{faysse2025colpaliefficientdocumentretrieval, loison2026vidorev3comprehensiveevaluation, teiletche2025modernvbert}, we demonstrate that cross-modal links can be leveraged to efficiently match query terms to image parts. In our work on contextual embeddings \sidecite{conti2025context}, we show existing structural links \emph{between} corpus documents can and should be exploited to facilitate retrieval. Through Large Language Model pretraining projects \sidecite{faysse_croissantllm_2024, meeus2024copyright}, we explore parametric memory consolidation and study which types of knowledge can be surfaced (searched) from the LLM memory through prompting (associative recall). Associative links come in many forms. This thesis explores only a subset of them, but aims to show that broadening the types of links used for retrieval can open fruitful research directions. In particular, I believe that many promising directions remain underexplored beyond the beaten (but nevertheless useful) path of improving text embeddings primarily through larger contrastive datasets and larger models.

Future research directions in line with this vision are further detailed.

\section{The Associative Memory Hierarchy Perspective}

Viewing \emph{search} solely through the lens of document retrieval is restrictive; a broader perspective is to understand search as \emph{memory access} across a hierarchy of storage media. Humans answer questions multiple ways: by relying on internal memory, by attending to information currently in view (consulting notes), or by looking up information online or in a library. All of these memory systems differ in capacity, latency, reliability, update cost, and provenance. As mapped in Table \ref{tab:mem-hiera}, LLM systems exhibit an analogous hierarchy.

Model weights act as compressed parametric memory; the current context, together with the key-value cache, provides a transient working memory; and document stores, databases, tools, or the web provide external non-parametric memory (Table \ref{tab:mem-hiera}). \sidenote{This analogy is strengthened by recent work interpreting Transformers through the lens of associative memory. In particular, \cite{zhong2025understandingtransformerperspectiveassociative} argues that both attention and feed-forward networks can be understood as memory systems, but with distinct retrieval and update properties. Attention constructs a dynamic associative memory over the current sequence, whereas feed-forward layers behave more like static learned associative stores.}

\noindent\textbf{Retrieval and Indexing.} Under this view, standard document retrieval (for RAG use cases, for instance) is simply the promotion of information from external memory into working memory. Similarly, LLM prompting and autoregressive generation are the retrieval mechanisms that move information from parametric memory to working memory. Within the working memory, the attention operation performs in-context retrieval using learned associative links between query and key representations (which could be seen as indexes). To continue with the analogy, standard \emph{document indexing} stores information from the working memory into external memory. Language Modeling through backpropagation inversely consolidates this information into the model weights, a sort of in-weights index triggered by future relevant activations.

This framework is useful in that it allows us to draw links between fields that today are mostly disjoint. My view is that some of the most interesting research problems in retrieval lie at their intersection. Work such as \emph{Transformer Memory as a Differentiable Search Index} \sidecite{tay2022transformermemorydifferentiablesearch} explicitly learns a corpus index in parametric memory. Instead of creating document embeddings through a model forward pass, works such as \sidecite{eyuboglu2025cartridgeslightweightgeneralpurposelong, kuratov2025cramming1568tokenssingle} optimize the text representation through backpropagation, inspired by the prefix tuning approach \sidecite{li2021prefixtuningoptimizingcontinuousprompts}.  Late Interaction \sidecite{khattab2020colbert} stems from the concept of better simulating the attention operation to allow for a matching operation more expressive than dot product similarity. Pushing this concept, Hypencoders \sidecite{killingback2025hypencoderhypernetworksinformationretrieval} convert queries into neural networks designed to take document representations as inputs and output relevance scores; one more example of a clever research design in which the barrier between parametric and external memories are blurred, enabling downstream associative recall that transcends the possibilities given by cosine similarity.

Finally, modern agentic search systems achieve success thanks to their ability to leverage all forms of memory jointly (parametric, in-context, external).
They combine strong parametric priors from the backbone LLM with tools to be able to navigate external memories (internet, corpora) and transfer information to their working memories where they can reason, all of this in a loop.
% This is how search should be: we leverage all possible priors and tools at our disposition and need to reason about things to undertand queries,analyze documents, etc...
These systems can even be reinforced by blurring the distinction between in-context memory and external memory with works like \emph{Recursive Language Models} \sidecite{zhang2026recursivelanguagemodels}.

Breaking down artificial preconceptions and unifying the document retrieval field with the broader ideas from associative memory research is a powerful avenue for future improvement. Very concretely, long-context sparse attention mechanisms from million-token context windows are inches away from document retrieval over external memories: both fields study how to represent information and index it as dense embeddings, such that further associative recall is triggered given a relevant query. In \emph{Self-Pruned Key-Value Attention: Learning When to Write by Predicting Future Utility} \sidecite{szilvasy2026selfprunedkeyvalueattentionlearning}, we devise ways to index information in a LLM KV Cache, but selectively learn when such information bears no signal and should not be persisted in memory. Such mechanisms would directly benefit most document retrieval systems.

\noindent\textbf{Research Idea.} Given more time, an idea I would have loved to explore is learning document embeddings solely through language modeling loss on unsupervised data. To do so, block sparse attention can be used to selectively include certain text sequences within the model training window, (softly) conditioned on the block's representation. Ideally, the block representation would be learned implicitly through soft gating techniques, similar to those used in our Self-Pruned KV paper. Blocks whose inclusion improves the language modeling objective would be assigned representations that make them more likely to be included, while unhelpful blocks would be filtered out. Importantly, block representations \emph{need not} represent block content itself; they merely serve as an indexing mechanism. While it is unclear whether such an approach could outperform modern contrastive learning methods trained on supervised retrieval data, it would offer a different and potentially scalable route to document representation learning. In particular, it would make it possible to train retrieval-oriented representations on internet-scale corpora using only the language modeling objective, without relying on explicit supervision signals.



\section{Towards Omnimodal Embeddings}

Retrieval is moving from a predominantly text-centric paradigm toward an \emph{omnimodal} one, in which useful evidence may be distributed across text, images, audio, video, code, structured data, and eventually even 3D assets. A first step in this direction was the rise of visual document retrieval: methods such as Document Screenshot Embedding (DSE) and ColPali showed that documents need not always be decomposed into OCR text and layout heuristics, but can instead be embedded directly from page images, preserving visual cues such as tables, figures, typography, and spatial organization \sidecite{ma2024unifyingmultimodalretrievaldocument,faysse2025colpaliefficientdocumentretrieval}. This line of work has since broadened from visual documents to richer forms of media. For instance, ColQwen-Omni \sidecite{faysse2025colqwenomni} extends the ColPali-style late-interaction retrieval paradigm toward audio and video on top of Qwen2.5-Omni \sidecite{xu2025qwen25omni}, while models such as Omni-Embed-Nemotron, e5-omni, BiDirLM, and Gemini Embedding 2 explicitly target unified embedding spaces for heterogeneous modalities including text, image, audio, and video \sidecite{xu2025omniembednemotron,chen2026e5omni, boizard2026bidirlm, shanbhogue2026geminiembedding2}.
% At the same time, the retrieval stack itself is diversifying: efficient late-interaction and small-model approaches, such as recent Mixedbread retrievers, suggest that strong first-stage retrieval primitives will remain essential even as larger agents and long-context models become more capable \sidecite{takehi2025mxbai}. In other words, omnimodal retrieval is not only a matter of adding more input types; it also requires deciding how different modalities should be represented, aligned, indexed, compressed, and compared.

A particularly important implication is that transfer across modalities can be positive rather than merely a source of interference. ModernVBERT provides an example in the visual-document setting: adding text-only query--document pairs to contrastive training improves visual document retrieval, suggesting that domain-specific supervision can sometimes be shared across modalities when the model has learned a sufficiently aligned representation space \sidecite{teiletche2025modernvbert}. This points toward a more general principle for omnimodal search: useful retrieval behavior may be learned from one modality and reused in another, provided that the embedding geometry supports reliable cross-modal comparison.

As AI-powered search becomes more agentic, the competitive edge of a system will increasingly depend on its ability to access and exploit heterogeneous sources of evidence.
Benchmarks such as BrowseComp and BrowseCompPlus already highlight the importance of persistence, iterative search, and variable test-time compute for finding hard-to-locate information on the web or in a corpus \sidecite{wei2025browsecompsimplechallengingbenchmark, chen2025browsecompplusfairtransparentevaluation}. However, such agentic procedures still benefit from strong ``first-layer'' retrieval models, which can cheaply select candidate evidence before more expensive reasoning or tool use is applied.
Not all information is equally reachable: some sources remain costly to access, poorly indexed, private, ephemeral, or expressed in unfamiliar modalities. Exploiting such information at scale will therefore remain a central challenge and a quality differentiator.


% \section{Measuring Search Performance}

% Search has a benchmarking problem. Classical information retrieval evaluation follows the Cranfield paradigm, in which systems are compared against a fixed corpus, a fixed set of queries, and a fixed set of relevance judgments \sidecite{cleverdon1967cranfield}. This abstraction has been extraordinarily useful, but it also hides several difficulties that become sharper in modern retrieval. Relevance judgments are expensive to collect, often subjective, and necessarily incomplete at web or enterprise scale, often mislabeling many relevant documents \sidecite{thakur2025freshstackbuildingrealisticbenchmarks}. Moreover, many benchmark queries are created with  knowledge of the corpus or even of the target document, leading to significant bias and test time discrepancies.

% A second issue is that the embedding community often optimizes  models for proxies that only partially correspond to search. Benchmarks such as MTEB are extremely valuable because they evaluate embeddings across many tasks, including retrieval, classification, clustering, reranking, semantic textual similarity, and summarization \sidecite{muennighoff2023mteb}. However, this breadth can blur an important distinction. In many document representation tasks, an embedding is asked to preserve the content of an input so that it can support classification, clustering, or similarity judgments. In information retrieval, by contrast, the embedding is better understood as an index: it need not faithfully represent the whole document, but must trigger the right associative match when a future query makes the document useful. Optimizing a single universal representation can therefore reward models for properties that are not always the bottleneck in retrieval. The relevant question is not only whether a vector represents a document well, but whether it makes the document reachable under realistic future queries. While strong IR focused benchmarks such as BEIR exist, they remain static test collections with fixed tasks and fixed notions of relevance that at terms tend to be overfitted  \sidecite{thakur2021beir}.

% A third difficulty is that search performance is not always directly verifiable. Some factual queries grounded in accessible digital sources are comparatively straightforward to evaluate: there is a short answer, a supporting source, and a plausible verifier. This is the regime targeted by benchmarks such as BrowseComp, which asks browsing agents to locate hard-to-find but short and verifiable answers \sidecite{wei2025browsecomp}. Yet many real search requests are underspecified, open-ended, exploratory, or value-laden. In these cases, there may be no unique answer, no stable gold document, and no easy way to decide whether the search process actually helped the user. Large multimodal benchmarks such as ViDoRe v3 show that it is possible to scale high-quality human annotation for complex retrieval and RAG settings, including visually rich documents, multilingual queries, localization, and verified answers \sidecite{loison2026vidorev3comprehensiveevaluation}. But such benchmarks are costly to build, and they still only approximate the deeper question: we search because we need information to do something. The core evaluation target should therefore be whether the search system improves downstream task performance, not only whether it retrieves a document marked relevant by annotators.

% This motivates a shift from model-centric IR benchmarks toward system-level evaluation. End-to-end benchmarks such as BrowseComp and BrowseComp-Plus better reflect the modern agentic pattern, where a system must plan, search iteratively, read evidence, reformulate queries, and decide when it has enough information~\cite{wei2025browsecomp,chen2025browsecompplus}. BrowseComp-Plus is especially useful because it replaces the opacity of live web search with a fixed, human-verified corpus, making it possible to disentangle the contributions of the backbone LLM, the retriever, and the agent scaffold~\cite{chen2025browsecompplus}. This kind of benchmark reveals an important dynamic of current agentic search systems: the LLM matters a great deal, the retrieval model also matters, and the scaffold that controls decomposition, search, reading, and stopping can matter just as much. Similar conclusions are suggested by work on retrieval-augmented reasoning and tool use, from WebGPT and ReAct to Self-Ask, IRCoT, HyDE, Search-R1, R1-Searcher, and ReSearch~\cite{nakano2021webgpt,yao2022react,press2022selfask,trivedi2023ircot,gao2023hyde,jin2025searchr1,song2025r1searcher,chen2025research}.

% This also suggests that scaffold engineering is currently one of the lowest-hanging fruits in search. Before changing the base model or the retriever, one can often improve a system by changing how it decomposes the query, how it generates intermediate searches, how it filters and reranks evidence, how it allocates context, how it cites sources, or how it decides to stop. OBLIQ-Bench makes this point from another angle: it identifies oblique queries, where the relevant documents instantiate latent or implicit patterns that a reasoning model can recognize once surfaced, but that current retrievers often fail to surface in the first place~\cite{tchuindjo2026obliq}. Recursive Language Models push the scaffold idea further by treating long prompts as an external environment and recursively calling sub-models over selected snippets, making the boundary between retrieval, long-context processing, and agentic decomposition increasingly fluid~\cite{zhang2025recursive}. These approaches suggest that future progress may come not only from better embedding models, but from better procedures for deciding what to retrieve, what to inspect, what to summarize, and what to ask next.

% Still, end-to-end benchmarks have their own weaknesses. They are hard to create, often artificially constructed, and static once released. Multi-hop and browsing benchmarks are useful precisely because they stress capabilities that simple retrieval misses, but their questions can also become stylized artifacts of the dataset construction process~\cite{yang2018hotpotqa,trivedi2022musique,ho2020twowiki,ferguson2020iirc}. Their scarcity makes benchmark overfitting a serious concern, especially because modern search systems expose many performance knobs: the backbone model, the retriever, the reranker, the query generator, the context allocator, the citation policy, the stopping rule, and the verifier can all be tuned against a small public leaderboard. This mirrors a broader problem in LLM evaluation, where static benchmarks are increasingly vulnerable to contamination, saturation, and gaming~\cite{chen2025staticdynamic}. A benchmark can remain useful while still being incomplete: it measures a capability slice, not the full utility of search.

% To improve search systems, we need scalable evaluation signals. This is a version of ``verifier's law'': tasks that are easy to verify can be optimized much faster than tasks where verification is expensive or ambiguous~\cite{wei2025verifierslaw}. Large-scale search providers can exploit weak supervision from user behavior, such as clicks, reformulations, dwell time, abandonment, and follow-up queries. These signals are noisy and biased, but they provide valuable aggregate evidence about whether users are satisfied or whether their information need remains unresolved~\cite{joachims2007implicit,hassan2013query,kim2014dwell,chuklin2015clickmodels}. Academic labs and smaller actors lack access to comparable interaction logs, so they need alternative sources of scalable feedback. Automated RAG evaluators such as RAGAS and ARES are one response, using LLM-based or learned judges to evaluate context relevance, faithfulness, and answer relevance with reduced human annotation cost~\cite{es2023ragas,saadfalcon2023ares}. However, such evaluators are themselves models, and therefore risk inheriting the same blind spots as the systems they evaluate.

Under a fixed decision model, better search systems should produce better situation assessments by locating deeper, fresher, or more decision-relevant evidence before it is fully priced in by the market. This connects naturally to the classical view of markets as mechanisms for aggregating dispersed information~\cite{hayek1945use,wolfers2004prediction,wolfers2006theory}. A benchmark could hold the reasoning model fixed and vary only the search system: each system would gather sources about political events, sports outcomes, earnings, policy decisions, or breaking news, and the same downstream model would convert the gathered evidence into calibrated forecasts or simulated trades. In principle, this would decorrelate retrieval quality from decision-model quality and measure whether search changes a measurable belief. The appeal is that prediction markets provide dynamic, externally priced targets rather than static gold labels, and their incentives can reduce some forms of annotation bias~\cite{berg2008prediction}.

\section{Improving Search Scaffolding}

 Modern search systems are no longer just embedding models queried once against a static index. They are increasingly agentic systems that decompose questions, generate intermediate queries, retrieve candidates, read evidence, rerank sources, allocate context, synthesize answers, and decide when to stop. This makes the \emph{scaffold} a central part of search performance. Benchmarks such as BrowseComp and BrowseComp-Plus make this visible: performance depends not only on the backbone LLM and retrieval model, but also on the procedure that controls iterative search and evidence use \sidecite{wei2025browsecompsimplechallengingbenchmark,chen2025browsecompplusfairtransparentevaluation}. Similar lessons appear in work on ReAct, Self-Ask, IRCoT, HyDE, Search-R1, R1-Searcher, ReSearch, and Recursive Language Models, where changes in decomposition, query generation, tool use, or recursive evidence inspection can substantially improve retrieval-augmented reasoning without necessarily changing the underlying model \sidecite{yao2022react,press2022selfask,trivedi2023ircot,gao2023hyde,jin2025searchr1,song2025r1searcher,chen2025research,zhang2025recursive}.

This suggests that scaffold engineering is currently one of the largest avenues for performance improvement in search. Improving the retriever or the backbone model often requires expensive training, large-scale data, or new infrastructure. By contrast, improving the scaffold can yield immediate gains. Creative ideas such as dumping model context in the filesystem and letting the model manipulate it \sidecite{zhang2026recursivelanguagemodels} can drastically improve performance in some tasks. Other benchmarks remain hardly solvable with current methods \sidecite{tchuindjo2026obliq} and while perhaps not the most fun, I suspect smart scaffolding might be the most direct way forward.

As search becomes more agentic, evaluating systems rather than isolated models will become increasingly important.


\section{Benchmarking Search Performance}

After agentic systems and end-to-end evaluation, the next step forward in benchmarking is to veer away from benchmarks artificially constructed to be hard and multi-hop, such as BrowseComp \cite{wei2025browsecompsimplechallengingbenchmark} or OBLIQ-Bench \sidecite{tchuindjo2026obliq}, and instead evaluate search by its ability to improve decisions under uncertainty. Many practical search tasks are difficult to benchmark because relevance is underspecified: users search not merely to retrieve a document, but to update their beliefs and act.


\noindent\textbf{Research Idea.} 
Prediction markets offer a natural testbed for this idea. They provide dynamic, externally priced estimates about future events, such as elections, policy decisions, sports outcomes, company results, or breaking news. Since market prices aggregate dispersed information and are continuously updated, they can serve as a measurable proxy for the current public belief about an event \sidecite{hayek1945use,wolfers2004prediction,wolfers2006theory,berg2008prediction}. A search system with genuine informational value should sometimes be able to improve on this baseline by finding deeper, fresher, or more decision-relevant evidence before it is fully reflected in the market. 

Concretely, by holding the final decision-making model fixed and varying only the search system, each system could gather different sources about the same market, and the same downstream model would convert the gathered evidence into a calibrated forecast and trading decision. The edge over other market actors is reflected in the financial outcomes. The fact the market is dynamic and quickly patches information arbitrage weights the value of gathered information automatically.
The evaluation target shifts from \emph{Did the system retrieve the annotated document?} to \emph{Did the system retrieve information that updates priors (beliefs) in a way that is possible to leverage?}

Given more flexibility, such environments could also become useful tests of source assessment, real-time reasoning, calibration, and more broadly general model intelligence in complex situations.

\section*{Search On}

Intelligence is becoming a commodity, sold to consumers by trillion-dollar companies. Blindly trusting state-of-the-art LLM outputs is becoming an almost rational decision: as we improve modeling and search tooling, model responses are most often going to be correct and well grounded in verifiable sources.

\emph{Searching} however, is often more than getting an exact answer to a specific question. To understand and truly value an answer, one must often first build prerequisite understanding, explore, reason, backtrack, synthesize... Other questions pop along the way. Bush says that we \emph{search} by exploring the maze of human knowledge but to a curious mind, this twisted path is beautiful and interesting; it leads through side quests and down rabbit holes. Answers to why the brick road is yellow in the \emph{Wizard of Oz} are surprisingly few Wikipedia links away from reading all about the Opium Wars.\sidenote{One of my favorite games I learnt from Professor Robert West consists in starting from a given Wikipedia article and navigating to another predetermined page using only in-article hyperlinks.}

Searching is the gateway to knowledge, but the path stimulates curiosity and bootstraps creativity. Shiny search tools are invaluable to progress as a society, and search agents are clearly the future. Sometimes however, aimlessly digging through the disorganized pile of parchments in the library of Alexandria is still the best option. Search on!
